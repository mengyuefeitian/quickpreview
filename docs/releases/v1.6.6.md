## v1.6.6 — 预览窗不再全局置顶，GB 级视频不再崩进程

本次包含两批修复：`1.6.5` 的「播放大视频崩溃」（issue #5），以及 `1.6.6` 的窗口层级问题。
`1.6.5` 未单独发布，内容一并汇总在这里。

---

### 修复

#### 1. 预览窗口全局置顶，挡住别的程序，没法切过去做对比

以前预览窗口是 `TopMost = true` 加 `SetWindowPos(HWND_TOPMOST)`，一旦弹出就压在整个桌面上。
想把 Word 或另一个资源管理器窗口切上来对照，预览窗永远挡在前面 —— 点不掉，也拖不开。

现在彻底不用全局置顶：

- 去掉 `TopMost`，改为设置 **owner 关系**（`GWLP_HWNDPARENT` 指向触发预览的那个资源管理器窗口）。
  owned 窗口由系统保证贴在 owner 之上；owner 不在前台时，它也不会越到别的程序前面，
  正好是「只浮在当前文件所在的资源管理器上层」。
- 新增前台变化跟随：切回那个资源管理器窗口时，预览窗自动浮到它上面
  （`SWP_NOACTIVATE`，不抢焦点）；切到 Word / 浏览器 / 另一个资源管理器窗口时什么都不做，
  预览窗自然沉到后面。
- 宿主资源管理器窗口关闭后自动解除 owner 关系。实测系统只解除关系，
  不会连带销毁预览窗，托盘图标和全局空格键照常在。

为什么不用 `SetWindowPos` 硬插 z 序：Windows 不允许后台窗口压住前台窗口，
硬插会被立刻弹回去（实测 0.7 秒后预览窗又回到资源管理器下面）。owner 关系由系统自己维护，
是唯一稳的做法。

#### 2. 开发与自动化测试时，预览窗口会抢焦点、挡在别人前面

`--preview` 排查入口新增 `--quiet`：内容照常渲染，但窗口用 `SW_SHOWNOACTIVATE` 显示，
不抢焦点、不参与层级跟随。回归脚本（`render_test.py`、`perf_test.py`、`dev_*.py`）已统一切到该模式，
跑测试不再打断正在用电脑的人。

#### 3. 播放 GB 级 mp4 时整个程序崩溃、托盘图标一起消失

反馈来自 [issue #5](https://github.com/mengyuefeitian/quickpreview/issues/5)。日志里三次崩溃
都发生在视频首包返回之后，`media.log` 记的是这样一行：

```
__local 206 xxx.mp4：Partial Content，1,975,618,907 字节（0–1,975,618,906 / 共 1,975,618,907）
```

播放器首包固定发 `Range: bytes=0-`（没有结束位）。本地文件服务当时按字面理解，
把**整个文件**塞进了一个响应体 —— 1.9GB。WebView2 需要吃下这么长的响应体，
浏览器进程被打爆，连带宿主在 `PInvoke.DispatchMessage` 抛 `SEHException` 直接退出。

对照同一台机器上的其它视频，规律很清楚：

| 文件 | 大小 | 结果 |
|---|---|---|
| 1.97 GB mp4 | 1.97 GB | 崩溃 |
| 1.32 GB mp4 | 1.32 GB | 崩溃（两次） |
| 同一个片子截取版 | 325 MB | 正常 |
| 另一个 mp4 | 57 MB | 正常 |
| 另一个 mp4 | 38 MB | 正常 |

分界线在 **GB 级**，与编码无关（325MB 那个同样是 H.265）。

现在单次响应最多 8MB，剩下的由浏览器继续发 `Range: bytes=<end+1>-`。
这对拖动进度条没有任何影响 —— 206 分片本来就是播放器的正常工作方式。
区间计算抽成纯函数 `FileRange.Resolve`，并配了 17 条离线断言
（GB 级首包 / 续包 / 末段不足一块 / 正好一块 / 越界收敛 / suffix / 多区间 /
空文件 / 200 全量不截断），跑 `python test-samples/dev_range_test.py` 可复现。

#### 4. 预览引擎崩了之后，宿主要跟着一起死

`SEHException` 会绕过 `Application.ThreadException`，一路冒到
`AppDomain.UnhandledException` —— 而那个处理器只能记日志、拦不住进程退出。
这就是「程序没了、还得手动重新启动」的原因。

现在消息循环外面接了一层自愈：接住异常 → 重建主窗体 → 气泡提示
「预览引擎异常退出，已自动恢复，该文件可能不受支持」。托盘图标和全局空格键继续可用，
10 分钟内最多恢复 3 次，避免真的坏掉时死循环。

#### 5. 退出路径上再记日志会抛 `ObjectDisposedException`

`Log.Shutdown()` 之后落盘线程已停、`_wake` 已释放，此时任何 `Log.E`
（崩溃自愈正要写日志）都会在异常处理里再抛一次，把进程带走。
现在停止写入之后改为同步落盘：这条日志既不会丢，也不会引发二次异常。

#### 6. `media.log` 看不到播放器到底要了哪一段

`__local` 记录里补上请求的 `Range` 原文；被分块时额外记一行
「本次 N 字节（客户端本可拿 M 字节）」。下次排查同类问题不用再靠猜。

### 验证

| 用例 | 结果 |
|---|---|
| `dev_topmost_check.py`（读 `WS_EX_TOPMOST` 位） | 新版 `0x00010000`，对照组 1.6.4 为 `0x00010008` |
| `dev_zorder_check.py`（打开在前 / 跟随资源管理器 / 不遮挡记事本） | 3/3 |
| `dev_range_test.py`（Range 区间纯函数） | 17/17 |
| `render_test.py` png / txt / docx / zip / xlsx | 全部 PASS |

`pdf` 在本机回归仍 FAIL，但拿未改动的 1.6.4 跑同一个文件同样 FAIL ——
这是本机无显卡导致的 `GpuProcessExited`，与本次改动无关。
